# 面向医学诊断场景的正式测评集 · 总结报告

编写日期：2026-09-13
产出目录：`/data/openpangu/正式测评集/`

## 一、一句话结论

做出了一份 **13 个维度、332 道题**的医学诊断测评集，题目 **全部来自 12 个公开权威测评集，无一道自编题**，只做筛选、抽样与格式统一。
**以中文为主**：中文 294 题、英文 38 题，英文占 11%；英文来源的题目已机器翻译为中文，译前原文逐条保留，可核对。
设计上借鉴 coding 大模型多维度榜单的思路：**不以题量取胜，以方位齐全取胜**，从知识底座一直测到智能体问诊和安全边界。

### 要做的事

为「面向医疗诊断场景的 openPangu 能力增强方案」准备一份正式测评集，用来支撑 L0–L5 六层实验的前后对比。

## 三、设计原则

**一、一个维度一种能力。**
coding 榜会把终端操作、前端、后端、agent、系统设计分开测，医学诊断同样不能只用一个准确率概括。每个维度单独报告，才能回答"加了某个模块到底让哪一项变强了"。

**二、方位全优先于题量大。**
单个维度 15–40 题，但 13 个维度覆盖了从知识记忆到安全边界的完整链路。宁可每个方位都薄一点，也不留空白。

**三、题目要能判分。**
每道题都写明评分方法与指标口径。能机器判的一律机器判，必须人工的明确写清人工评什么。

**四、来源要能追溯。**
每道题带 `source`（数据集、机构、链接、许可、论文、原文件名）和 `provenance`（采集日期、发布时间、更新时间、污染风险）。

**五、中文优先。**
面向中文临床场景，题目以中文为主。英文来源的题目翻译成中文，译前原文放进 `original_en`，翻译这件事本身也留痕（`translation` 字段）。

## 六、中文化处理

### 为什么要做

面向中文临床场景，题目以中文为主更贴合实际使用，也便于人工评审与答辩讲解。同时保留少量英文原题，用于观察同一能力在中英文下的表现差异。

### 结果

| 情况 | 题量 | 说明 |
| --- | --- | --- |
| 中文原题 | 43 | CMB、CMExam、MedQA 中文版、IMCS-V2-MRG、CmedqaRetrieval |
| 机器翻译为中文 | 289 | DeepSeek（`deepseek-chat`），温度 0 |
| 保留的英文原题 | 38 | 每个受影响的维度留 2–5 道 |

英文占比 11%，集中在 D01（5）、D02（2）、D03（5）、D07（3）、D08（5）、D09（5）、D10（4）、D11（4）、D12（5），其余维度全中文。

### 怎么保证质量与可复现

1. **逐条留原文。** 每道译题的 `original_en` 里按字段路径保存译前英文，例如 `question`、`options.A`、`rubric.5.criterion`，可逐条比对。
2. **逐条留痕。** 每道译题带 `translation` 字段，写明模型、方向与"机器翻译，正式使用前建议由医学背景人员校对"。
3. **术语规则前置。** 翻译提示词里固定要求：医学术语用中国大陆临床通用译法，数字、单位、化验值、英文缩写（CT、MRI、BMI、eGFR）保留原样。
4. **结果缓存。** 译文按原文哈希缓存在 `_build/translation_cache.json`，共 1319 段。重跑构建时全部命中缓存，**不重复调用接口，结果完全一致**，也不依赖网络。
5. **结构化字段不动。** 来源名、指标名、`axis`、`role` 等程序用字段不参与翻译，避免影响判分。

| | 内容 |
| --- | --- |
| 译前 | A 55-year-old postmenopausal woman reports experiencing sharp pain in the right groin for the past two weeks, which is alleviated by standing. |
| 译后 | 一位55岁绝经后女性报告过去两周出现右侧腹股沟锐痛，站立时缓解。 |

## 七、构建过程

三步流水线，脚本都在 `_build/`，可重复运行：

```
download.py   从 HuggingFace 镜像拉原始数据到 _raw/（已下载且大小一致会跳过）
build.py      筛选、抽样、中文化、统一字段，产出 13 个 jsonl 与 manifest.json
verify.py     校验结构、答案、id 唯一性，并打印来源分布
```

### 关键处理点

**一、判题只看问句落点。**
病例正文里出现"治疗史""既往用药"是正常的，不能因此把整题判成治疗题，所以判定只看题干最后 100 个字。治疗、用药、护理、手术、预防、中医理论、药代、伦理、统计类题目全部剔除。

**二、同一病例的小问互斥分配。**
CMB-Clin 一个病例带多个小问，先按规则分到「鉴别 / 检查 / 诊断」三类，每小问只进一个维度，避免同一题出现在两个维度里。

**三、抽样前先去重。**
源数据里存在重复题（如 CMExam），先去重再抽样，否则重复题会挤掉本可以选进来的其他题。

**四、抽样可复现。**
固定随机种子 20260913，采用等距抽样而不是随机取头尾，保证覆盖整段数据、不挑题。

**五、格式统一。**
13 个维度共用一套字段，下游一套评测程序就能跑全库。内嵌在题干里的重复选项（MedXpertQA）剥掉；答案文本映射回选项字母（MedQA 原数据存的是选项原文而非字母）；原文里夹带的 HTML 残留（PubMedQA）清掉。

**六、正文保真。**
做全角半角归一化时会误伤参考答案里的 ①②③ 分点编号，已单独保护，分点结构不会被破坏。

**七、翻译要能漏检出问题。**
构建后专门跑了一轮英文残留扫描，发现选择题选项因为键名是 A/B/C 而被漏翻，修正后重新翻译并复查。

## 十、时间因素的考虑

**一、优先用新数据。**
D08（2025）、D09–D11（2025）、D12（2025-12 更新）都是近期发布，被预训练语料覆盖的概率低，更能反映"没见过的题"上的真实能力。

**二、考试类数据只作底座。**
CMB-Exam、CMExam、MedQA、MMLU 高度可能已进入预训练语料，`contamination_risk` 一律标高或极高，共 103 题。它们只出现在 D01 D02 D03 D04 这类知识型维度，正式报告不能拿这些分数证明诊断能力强。

**三、真实临床数据优先。**
D03（NEJM CPC 真实疑难病例）、D05（住院病历）、D06（真实医患问诊）、D07（OSCE 场景）来自真实临床，记忆效应弱。

**四、每题带时间戳。**
`provenance` 记录采集日期、数据集发布时间与更新时间，隔期复核时能看出哪些来源已经过时。

## 十一、关键决策记录

| 决策 | 理由 |
| --- | --- |
| 去掉多模态维度 | 按最新要求，全库改为纯文本，删除原 D09 与 30 张图片 |
| 英文来源题机器翻译成中文 | 面向中文临床场景；逐条保留原文与翻译留痕，质量可核 |
| 保留 38 道英文原题 | 英文必须为少数（占 11%），但要能观察跨语言一致性 |
| 用 13 个窄维度而不是 3–5 个大类 | 大类的分数涨了说不清是哪种能力涨了，拆细才能对应 L0–L5 的消融实验 |
| 每维度只取 15–40 题 | 目标是覆盖方位，不是刷统计功效；题量小的代价已在 README 里用置信区间说明 |
| CMB-Clin 的小问互斥分配 | 同一小问不能同时算两个维度，否则维度分之间不独立 |
| 判题只看题干最后 100 字 | 病例正文提到治疗史是正常的，不能因此误判题型 |
| 抽样前先去重 | 源数据有重复题，不去重会挤掉其他候选 |
| 翻译结果落缓存而不落 key | 缓存让构建可复现、离线可跑，同时不把密钥写进任何项目文件 |
| D03 保留 NEJM 的 top-k 命中口径 | 沿用 npj Digital Medicine 2024 论文协议，不用自创口径 |
| 从 HealthBench 切出三个维度 | 一份权威来源同时覆盖急症转诊、信息不足、沟通三类边界能力，比凑三份来源更一致 |
| 排除 CMB-test | 官方测试集不公开答案，无法判分 |
| 排除 MedBench-Safety-Ethics | 社区镜像、无许可、版本无法核验，与权威性要求冲突 |

## 十二、已知局限

**一、译文需要医学校对。** 289 道译题由机器翻译，虽已逐条保留原文，但正式对外前建议抽查，重点是 D09–D11 的评分量表（836 条）和 D12 的计算题。

**二、D07 需要先搭模拟患者。** 题目给出了隐藏病史与查体、检查结果，但要跑起来必须先实现一个按隐藏信息作答的模拟患者，否则这道题无法评测。这部分工作量和协议尚未确定。

**三、中文真实疑难病例金标准缺失。** D03 的 NEJM 部分只有 5 道且为英文，因为公开数据里没有中文的真实疑难病例金标准集。

**四、部分来源是社区镜像。** AgentClinic 与 CmedqaRetrieval 没有许可声明，本集按研究用途收录，对外发布前需再确认。

**五、单维度题量小，分数噪声大。** 25 题规模的维度，准确率 50% 时 95% 置信区间半宽约 ±20 个百分点。结论应尽量看全库口径，或使用同题配对检验。

**六、`key_points` 与 rubric 需人工复核。** 要点由脚本从参考答案自动抽取（148 条），量表来自 HealthBench 原文并由机器翻译，正式评分前建议由医学背景人员过一遍。

## 十三、后续建议

**一、译稿医学抽查。**
优先抽查 D09–D11 的评分量表和 D12 的计算题，这两类对措辞与数值最敏感。

**二、补主动问诊的模拟患者。**
这是当前最大的一块缺口。建议先定协议：模拟患者按 `context` 里的隐藏信息作答、只回答被问到的问题、限制提问轮数上限，评分同时看诊断正确率与信息召回率。

**三、做难度探针。**
正式评测前用裸模型跑一遍全库，标出全员满分（没有区分度）和全员零分（多半题目本身有问题）的题。这一步会直接影响 L0 基线的可信度。

**四、定稿后冻结版本。**
要加题就开 `v2` 目录，不要在 `v1` 上改题，否则前后两次实验的分数不可比。

**五、按需继续扩充中文。**
当前中文占 89%。若还要提高，可继续增加 CMB-val、CMExam 的抽样量，或把 D03 剩余的英文病例换成中文考试类鉴别题。
