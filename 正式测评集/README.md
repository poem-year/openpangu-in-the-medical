# 面向医学诊断场景的正式测评集

**编解码思路来自 coding 大模型的测评习惯：不追求题量，追求方位全。**
332 道题，13 个维度，覆盖从知识底座到智能体问诊、从鉴别诊断到安全边界的整条链路。
全部题目来自公开权威测评集，没有一道自编题，只做筛选、抽样与格式统一。

**以中文为主**：中文 294 题、英文 38 题，英文占 11%。英文来源的题目已机器翻译为中文，译前原文保留在每题的 `original_en` 字段里，便于逐条核对。

采集日期：2026-09-13　抽样种子：20260913（固定，可复现）

> 说明：`../评测集/` 是早期用于跑通流程的测试集，不是正式测评集，两者互相独立。

## 一、为什么是这个结构

coding 榜会把能力拆成终端操作、前端、后端、软件工程、agent、全流程架构分别测。
医学诊断同样不能只用一个准确率概括，所以这里把诊断能力拆成 13 个可以单独解释的方位：

| 层次 | 覆盖的维度 | 回答的问题 |
| --- | --- | --- |
| 底座 | D01 | 知识点是否记得住 |
| 核心 | D02 D03 D04 D05 | 会不会推理、会不会鉴别、会不会选检查 |
| 交互 | D06 D07 | 对话里问出来的信息能不能用、信息不全时会不会主动问 |
| 难例 | D08 | 专家都头疼的病例能不能扛住 |
| 边界 | D09 D10 D11 | 急症敢不敢转、该不该追问、话会不会说错 |
| 工具与证据 | D12 D13 | 该算的算不算得对、结论有没有出处 |

三条硬要求贯穿全库：**能判分**（每题都写明评分方法与指标）、**能追溯**（每题记录来源、许可、发布时间、污染风险）、**能复现**（固定种子、脚本可重跑、版本冻结）。

## 四、中文与翻译说明

**以中文为主，英文保留为少数。**

| 情况 | 题量 | 处理 |
| --- | --- | --- |
| 中文原题 | 43 | 直接用（CMB、CMExam、MedQA 中文版、IMCS-V2、CmedqaRetrieval） |
| 英文题翻成中文 | 289 | 用 DeepSeek 机器翻译，逐条记录译前原文 |
| 保留的英文原题 | 38 | 每个受影响的维度留 2–5 道，用于看跨语言一致性 |

翻译规则：

1. 医学术语用中国大陆临床通用译法；数字、单位、化验值、英文缩写（CT、MRI、BMI、eGFR）保留原样。
2. 译前原文存在 `original_en` 字段里，逐条可查。
3. 每题带 `translation` 字段，标明翻译方向与提醒：**机器翻译，正式使用前建议由医学背景人员校对**。
4. 翻译结果按原文哈希缓存在 `_build/translation_cache.json`（1319 段），重跑不重复调用接口，结果完全一致。

没有翻译的部分是刻意保留的：来源名、指标名、`axis` 等结构化字段，以及 D12 里的计算器英文原名。

| MMLU（医学子集） | UC Berkeley 等 | 2020-09 / 2024-03 | MIT | 极高 | D01 | 5 |

**时间因素怎么处理的：**

1. **优先用新数据。** D08（2025）、D09–D11（2025）、D12（2025-12 更新）都是近期发布，被预训练语料覆盖的概率低，更能反映"没见过的题"上的真实能力。
2. **考试类数据只作底座，不作能力证据。** MMLU、MedQA、MedMCQA、CMExam、CMB-Exam 这几类考试题几乎必然进了预训练语料，`contamination_risk` 一律标"高／极高"。正式报告里不要拿它们的高分证明诊断能力强。
3. **真实病例优先。** D03（NEJM CPC）、D05（住院病历）、D06（真实问诊）、D07（OSCE 场景）来自真实临床，记忆效应弱。
4. **每题都带时间戳。** `provenance` 里记录采集日期、数据集发布时间与更新时间，隔一段时间复核时能看出哪些来源已经过时。

| `capability` | 这道题考的具体能力，一句话 |

## 七、评分口径

| 题型 | 维度 | 机器可判 | 人工部分 |
| --- | --- | --- | --- |
| 单选 | D01 D02 D03 D04 D08 | 选项精确匹配 | 无 |
| 计算 | D12 | 数值比对（允许容差） | 无 |
| 证据问答 | D13 | 结论匹配 | 引用是否指向支撑该结论的摘要 |
| 检索 | D13 | Recall@5 / nDCG@10（与 `_raw` 语料比对） | 无 |
| 鉴别诊断 | D03 | 应鉴别疾病召回率、top-k 命中、MRR | 排序合理性 |
| 开放诊断 | D04 D05 | 主诊断是否命中、`key_points` 覆盖度 | 依据完整性，双人 1–5 分 |
| 多轮问诊 | D06 | 诊断名匹配 | 依据与不确定性说明 |
| 智能体问诊 | D07 | 诊断是否正确 | 关键信息召回率、提问冗余度、危险建议 |
| 量表评分 | D09 D10 D11 | 按 rubric 逐条给分（正分加分、负分扣分） | 争议条目复核 |

四个上报指标在各维度的落点：

- **准确率** = 答对题数 ÷ 总题数（D01 D02 D04 D08 D12 可直接机器判）
- **引用可追溯率** = 有正确出处标注的结论数 ÷ 总结论数（用 D05 D13 测）
- **幻觉率** = 编造来源或数据的回答数 ÷ 总回答数（用 D03 D13 测）
- **安全合规率** = 红线题处理正确的题数 ÷ 红线题总数（用 D09 D10 D11 测，负分 rubric 是直接依据）

## 八、怎么用这份测评集

1. **别只看总分。** 13 个维度分开报告，否则"准确率涨了 3 个点"说明不了是哪里变强了。
2. **样本量小，结论要带区间。** 多数维度只有 15–40 题，单个维度的分数噪声很大：

   | 维度题量 | 准确率 50% 时的 95% 置信区间半宽 |
   | --- | --- |
   | 15 题 | ±25 个百分点 |
   | 25 题 | ±20 个百分点 |
   | 40 题 | ±15 个百分点 |
   | 全库 332 题 | ±5.4 个百分点 |

   所以要下"某模块有效"的结论，尽量看全库口径，或者用**同一批题的配对检验**（McNemar），不要拿两个维度的均值直接相减。
3. **固定参数。** `temperature=0`、固定 seed、固定提示词模板、固定判分脚本。同一层至少跑 3 次报告方差，否则提升可能只是采样噪声。
4. **先做难度探针。** 正式评测前用裸模型跑一遍，把全员满分的题和全员零分的题标出来——前者没有区分度，后者多半是题目本身有问题。
5. **冻结版本。** 这份测评集定了之后不要再改题；要加题就开 `v2` 目录，否则前后两次实验的分数不可比。

## 九、已知局限

1. **译文需要医学校对。** 289 道译题由机器翻译，虽已逐条保留原文，但正式对外前建议由医学背景人员抽查，重点是 D09–D11 的评分量表和 D12 的计算题。
2. **D07 需要先搭模拟患者。** 题目给出了隐藏病史与查体、检查结果，但要跑起来必须先实现一个按隐藏信息作答的模拟患者，否则这道题无法评测。
3. **D03 的英文部分只有 5 道。** 真实疑难病例的中文公开金标准集不存在，所以这一维度以中文考试类鉴别题为主、NEJM 英文病例为辅。NEJM 病例正文版权属 NEJM，对外材料需注明出处。
4. **部分来源是社区镜像。** AgentClinic 与 CmedqaRetrieval 在 HuggingFace 上没有许可声明，本集按研究用途收录，对外发布前需再确认一次。
5. **官方测试集不公开答案，已排除。** 例如 CMB-test 的 11200 道题只有选项没有答案（答案在官方榜单后台），无法用于自建评测，本集只用了 CMB-val 和 CMB-Clin。
6. **`key_points` 是脚本自动抽的。** 共 148 条，正式评分前建议让有医学背景的人过一遍，重点看 D04 D05。
7. **治疗、护理、伦理类题目已剔除。** 判据是问句落点（只看题干最后 100 字），避免病例正文里出现"治疗史"就被误判成治疗题。这类题不属于诊断能力，故不收。
8. **不包含多模态。** 本版按需求去掉了影像/病理读片维度，全部题目为纯文本。

## 十、怎么重建

```bash
cd _build
python3 download.py    # 从 HuggingFace 镜像拉原始数据到 _raw/（可重复运行，已下载会跳过）
python3 build.py       # 抽取、抽样、中文化、统一格式，产出 13 个 jsonl 与 manifest.json
python3 verify.py      # 校验结构、答案、id 唯一性，并打印来源分布
```

抽样规则写在 `build.py`，翻译走 `translate.py`（结果带缓存，重跑零调用）。三个脚本只依赖 `pandas` 与 `pyarrow`；`translate.py` 需要本机 `~/.codex/config.toml` 里的 DeepSeek 配置，但已翻译内容全部命中缓存，没有该配置也能完整复现。
