# 评测报告存档

这里放**历次评测的报告快照**（每轮几十 KB），完整原始结果（`predictions.jsonl` /
`scores.jsonl` / `contexts.jsonl`，一轮几 MB 到几十 MB）仍在 `eval/runs/` 下，
不进 git、随时可重跑。

补录新轮次：

```bash
bash 评测报告/collect.sh                       # 收集全部已完成的轮次
bash 评测报告/collect.sh L3-slow-v3 L2-slow-v3  # 只收指定轮次
```

然后在下面的索引表里登记一行。

## 二、怎么读这些数

- **两个「报告」文档是结论层**：[`../L0基线评测报告.md`](../L0基线评测报告.md)（基线）、
  [`../L2L3检索层评测报告.md`](../L2L3检索层评测报告.md)（检索层 + 截断诊断）。
  本目录的 `summary.md` / `report.html` 是**单轮原始产出**，逐维度、逐题可查。
- **看分数前先看截断数**。旧协议下 L2 有 168/312 题跑满预算没写出答案，
  那一轮的准确率不能当作「检索有没有用」的结论。
- **引用可追溯率只在 L2/L3/L5 有意义**；L0 没有知识库，按口径固定为 0，
  不代表模型不引用（它引用的是题面材料，指标里不认）。
- 每轮的 `skipped.jsonl` 记录被跳过的题及原因（D07 模拟患者 15 题、D13 检索 5 题），
  不静默丢弃。

## 三、文件说明

| 文件 | 内容 |
| --- | --- |
| `summary.md` | 人读版：四个上报指标 + 分维度表 + rubric 表 |
| `summary.json` | 机器读版（同一份数据的结构化形式） |
| `report.html` | 带样式的单轮报告 |
| `compare.md` | 慢思考 / 快思考对比（仅 L0 那一对有） |
| `skipped.jsonl` | 跳过的题与原因 |
| `collect.sh` | 从 `eval/runs/` 快照报告类文件到本目录 |
